# Сравнительный анализ AI Coding Agents

## 1. Как проходила работа с агентами

Для выполнения работы я использовала двух разных AI-агентов:
1. **Агент №1 — Trae** (работала через встроенный IDE-интерфейс).
2. **Агент №2 — OpenCoder / Open-Coder** (работала через консольный CLI в VS Code).

Ниже подробно описываю, с чем столкнулась на каждом этапе.

---

### 1.1. Агент №1: Trae (IDE-агент)

#### Какие задачи я ставила агенту
* **Разбор проекта и документация:** Проанализировать старый Django-код, выявить стек и написать файл `ANALYSIS.md`.
* **Поиск багов и требований:** Найти дыры в безопасности REST API (все было открыто без авторизации), ошибки в фоновых задачах Celery и проблемы с обновлением цен.
* **Рефакторинг:** Обновить `requirements.txt` под свежий Python, поправить `settings.py` и починить кривой роутинг в `urls.py` (где из-за пропущенного слэша страницы входа отдавали 404).
* **Виртуальный портфель и графики:** Добавить модели `Portfolio` и `PortfolioPosition`, сделать страницу портфеля и написать генерацию моковых данных для графиков Plotly.
* **Верстка:** Исправить наложение графика на кнопки и починить вылезшие служебные комментарии.

#### Основные промпты
> `Проанализируй исходный код текущего Django-проекта Investing Demo. Мне необходимо сформировать подробный технический отчёт. Создай в корне проекта файл ANALYSIS.md...`

> `Исправь отображение графика Plotly и верстку на странице детализации акции... Оберни контейнер Plotly в отдельный div с явным отступом снизу (margin-bottom: 40px;)...`

#### Ошибки и проблемы, с которыми столкнулась
* **Сломанные комментарии Django:** Агент вставил многострочный комментарий `{# plotly.js v3... #}` прямо в `base.html`. Django-шаблонизатор так делать не умеет, и эта строчка просто вылезла в самом верху готового сайта.
* **Конфликт версий Plotly:** Trae использовал устаревшие параметры `show_link` и `link_text`, из-за чего библиотека Plotly 7.x падала с ошибкой в консоли браузера.
* **Плоский график:** При получении цен из API агент случайно отбрасывал дробную часть (`nano`) и берег только целые рубли (`units`). Из-за этого график цены акции рисовал абсолютно плоскую горизонтальную линию.
* **Сломанная верстка:** Агент применил несуществующий Bootstrap-класс `col3` вместо `col-md-3`, из-за чего разметка карточки акции "поплыла".

#### Затраты времени и итерации
* **Итераций:** 8 основных шагов + 1 служебный запрос на сборку истории.
* **Время:** 1 день.

### 1.2. Агент №2: OpenCoder

#### Какие задачи я ставила агенту
* **Глубокий технический аудит:** Написать детальный `ANALYSIS.md` с точностью до строчек кода и нумерацией уязвимостей (DEF-01...DEF-33).
* **Безопасность и API:** Закрыть анонимный доступ к REST API, настроить `.env` и написать собственный REST-клиент для T-Invest вместо неработающего SDK.
* **Решение конфликтов базы данных:** Разобраться с постоянными ошибками `OperationalError: no such table` и `no such column: purchase_price`, аккуратно сбросить базу и пересоздать миграции.
* **Новый функционал (Задание №4):**
  * *Списки наблюдения (Watchlist)* с отслеживанием целевых цен.
  * *История цен* с графиками Chart.js и динамикой рынка.
  * *Симулятор стратегий* (бэктестирование стратегий: ценовые уровни, просадка, скользящие средние SMA).
* **База акций с MOEX:** Пойти в открытый API Московской биржи (MOEX ISS) и подтянуть 403 реальные акции без всяких API-токенов.

#### Основные промпты
> `У нас возник рассинхрон между базой данных и миграциями... Сделай полный чистый сброс схемы: останови runserver, удали db.sqlite3, пересоздай миграции...`

> `Мы приступаем к выполнению Задания №4... реализуй мониторинг, историю цен, симулятор инвестиционных стратегий... и придумай где и как взять базу акций`

#### Ошибки и проблемы, с которыми столкнулась
* **Зависший процесс (PID 76356):** В фоновом режиме остался запущен старый `runserver`. Он продолжал держать в памяти старую схему базы, из-за чего Django падал с ошибкой `no such column: purchase_price`. Клод сам догадался найти и убить этот процесс через `taskkill`.
* **Проблемы с регистром в SQLite:** При проверке названий списков наблюдения на кириллице встроенный `iexact` в SQLite не работал. Пришлось попросить агента переписать проверку на `casefold()`.
* **Отсутствие токена T-Invest:** Не получалось загрузить акции через Т-Банк из-за проблем с сертификатами Минцифры. Решили проблему тем, что агент написал новый парсер для Московской Биржи.

#### Затраты времени и итерации
* **Итераций:** 12 диалоговых шагов.
* **Время:** 1 день.

## 2. Сравнение агентов (Итоги)

### 2.1. Сравнительная таблица

| Критерий | Trae (Agent #1) | OpenCoder (Agent #2) | Кто лучше? |
| :--- | :--- | :--- | :--- |
| **Самостоятельность** | Работает с файлами, но требует частых проверок и ручного перезапуска команд. | Сам выполняет команды в терминале, ищет зависшие процессы, пишет миграции и запускает тесты. | **OpenCoder** |
| **Решение багов базы данных** | Исправляет мелкий код, но запутался в рассинхроне миграций SQLite. | Нашел причину конфликта полей (`purchase_price` vs `average_price`) и сам убил зависший процесс. | **OpenCoder** |
| **Качество верстки и HTML** | Допустил баг с комментариями Django и случайно наложил график на кнопки. | Сделать все аккуратно на Chart.js и Bootstrap 5 без визуальных наложений. | **OpenCoder** |
| **Тестирование** | Полагался в основном на мою визуальную проверку в браузере. | Написал и успешно прогнал **111 unit-тестов** на Django TestCase. | **OpenCoder** |
| **Находчивость (если нет данных)** | Сделал простые моки цен для Plotly. | Написал полноценный парсер для MOEX ISS API и подгрузил 403 реальные акции. | **OpenCoder** |

### 2.2. Мои впечатления и выводы

* **Trae:** Понравился удобным визуальным интерфейсом прямо в IDE. В нем наглядно видно, какие строчки кода меняются. Но как помощник он требует постоянного контроля: то комментарий криво вставит, то класс Bootstrap перепутает.
* **OpenCoder:** Оказался мощным автономным инструментом. Он работает через консоль, но берёт на себя всю рутину: сам запускает миграции, пишет тесты, правит ошибки базы данных и даже находит альтернативные решения (как с акциями MOEX).

**Итоговый вывод:** Для быстрой правки верстки Trae весьма удобен за счет visual diff. Но если нужно сделать сложный рефакторинг, починить базу данных и закрепить всё надежными тестами — **OpenCoder показал себя намного сильнее и автономнее**.
